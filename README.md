# 声间 · Audio Switch

> `refactor/ui` 分支新增独立的 [新前端](frontend/README.md)：浏览器使用模拟数据，Tauri 桌面版已接入主面板操作；旧后台保持只读。第三阶段自动验证及待完成的实机验收见 [STAGE-3.md](frontend/STAGE-3.md)。构建输出在 `staging/`，没有替换日常使用的 `bin/` 或旧发布流程。

用于 Windows 10 / 11 x64 的轻量音频设备管理工具。支持浅色和深色原生界面，前端按需启动，关闭窗口时整个界面进程退出。

当前版本 **v0.11.1**：新增游戏模式、空闲下载与下次启动安装的自动更新，调整更新开关位置并修正程序图标。升级后的自动更新默认开启，可在“检查更新”窗口关闭。完整变更及下载说明见 [v0.11.1 发行说明](releases/RELEASE-NOTES-v0.11.1.md)。

## 必要文件检查

主面板左侧 **文件检查** 可检查当前程序目录，发现必要文件缺失或损坏后自动尝试修复。首次启动托盘以及打开面板／提示窗口时也会检查；配套文件恢复并核验通过后继续启动，仍有问题时显示原因，停止本次启动。已有后台时重复的后台启动仍直接退出。

只要求 3 个运行文件：`AudioSwitch.exe`、`AudioSwitch.exe.config`、`vendor/svcl/svcl.exe`。说明、帮助和许可文件（`vendor/svcl/readme.txt`、`vendor/svcl/svcl.chm`、`LICENSE`、`NOTICE.txt`、`THIRD_PARTY.md`）缺失或被改动不影响检查结果，不自动补齐；正常发布包仍保留这些文件，分发规范不变。配套文件按编译时内嵌的长度和 SHA-256 校验，SVCL 保留固定版本校验。主程序检查名称、版本、x64 平台及自身 SHA-256：除保存自身校验值的 64 字节槽外，所有字节都参与校验。

运行配置和 SVCL 会从程序内置副本离线恢复，写入前验证来源，保存原文件到程序目录 `repair-backups/`，写后重新检查；失败时尝试恢复原文件并核验，不能恢复会明确报告。修复不删除文件或清理备份。主程序异常时尝试下载**当前版本**的官方包，验证 GitHub 附件摘要和必要文件后，由独立助手正常关闭本目录实例、备份并替换 3 个运行文件，再重新启动。此过程复用更新事务和 `update-backups/`；不会为修复自动升级或降级。当前版本未发布修复包、离线、文件占用或目录不可写时，显示失败原因，允许重试或打开发布页，不会报告已经修复。

整套文件一起移动后仍可校验；只移动 EXE 时可补回运行配套文件。此功能不改变自启登记，搬家后的自启仍按下方说明处理。用户配置、已有备份、日志、额外文件和系统安装的 Dolby 组件不纳入此检查，也不会因此被修改。

可独立运行 `AudioSwitch.exe --check-files` 进行检查与修复；配套文件修复不启动托盘，主程序修复会重启工具。加 `--quiet` 则为**只读检查，不尝试修复、不联网**，退出码为 0（通过）、2（不通过）、3（正在更新，未检查）。更新助手和 Dolby 辅助进程保留各自已有的校验流程，不进入普通启动检查。没有常驻轮询；仅主程序需修复时联网，下载阶段可取消。构建清单和修复副本均内嵌于 EXE，固定 8 文件发布包不变，构建目录的 `integrity-manifest.txt` 无需分发。

此功能用于发现文件缺损，不代替发布者签名或防恶意篡改认证；如果 EXE 或运行时配置损坏到 .NET 无法进入程序，Windows 的启动错误可能先出现，此时也应重新解压完整包。生成 EXE 后再次修改、签名或加壳会改变校验值，须调整构建流程后重新生成，不能直接处理成品。

## 游戏模式

主面板左侧和托盘右键菜单都有 **游戏模式** 开关，两处使用同一设置，保存后重启仍然生效。开启时暂停自动检查更新、后台下载及全屏／负载检测，并取消尚未完成的自动网络请求；已下载的包保留，游戏模式开启时下次启动也暂不自动安装。关闭后恢复未完成的自动更新流程，仍按空闲条件下载，安装仍等下次启动。主动点击“检查更新”或“文件检查”属于手动操作，继续可用。

设备识别、优先级、白名单、手动切换和 Dolby 音效跟随保留。游戏模式下，设备事件从约 150 ms 合并改为 500 ms，连续通知仍从首条开始计时，不无限拖延；这样减少短时事件引起的重复设备读取和处理，自动响应可能多等几百毫秒。没有事件时不轮询设备。主面板刷新从 1.5 秒降为 5 秒，设备提示窗口从 0.3 秒降为 1.5 秒，点击操作仍立即发送。关闭窗口仍退出对应界面进程。退出游戏模式后恢复正常频率，正在等待处理的一批事件保留原截止时间。

## 开机自启

主面板左侧的 **开机自启** 开关用于当前 Windows 用户，首次默认关闭。开启后，登录 Windows 时只启动托盘后台，不弹出管理面板；已有后台时重复启动会直接退出。关闭开关会取消本程序的自启，不退出当前后台。

使用 Windows 官方的当前用户 `Run` 启动项，不需要管理员权限，不安装服务或计划任务。开关读取本机实际登记状态，写入后读回确认，失败会尝试恢复并说明结果。仅管理名为 `AudioSwitch` 的启动项；无法识别的同名项不覆盖。程序搬到新目录后，可在新位置重新开启开关，更新自启路径；原地升级不改变路径。

位置变化时会区分“自启指向其他位置”和“原自启路径已失效”，点击开关下方说明可查看原登记路径、当前路径和处理办法。检测本身不改注册表，重新开启开关才更新位置；如果程序运行中被搬动、当前 EXE 已不可访问，则禁止再次登记失效路径，提示退出后从新位置重开。若旧目录的后台仍在运行，新位置的手动启动会提示先退出旧后台，不再偷偷打开旧面板。文件名应保留 `AudioSwitch.exe`，改名后先恢复文件名再设置自启。

自启修改请求绑定当前程序路径及页面读到的启动项。其他窗口或程序改变启动项后，旧页面的操作会被拒绝并刷新；失败恢复不会覆盖已经观察到的外部修改。

自启属于本机设置，不包含在音频配置的导入／导出中。Windows 的启动应用禁用状态或组织策略仍可能阻止自启；若登记后登录时没有启动，请检查 Windows 设置或任务管理器中的“启动应用”。自动测试不修改真实启动项，实际注销／重新登录需按 `MANUAL-TESTS.md` 验收。

## 软件内更新

从已有的 v0.10.1 继续使用 `v主版本.次版本.修订号` 的版本体系。程序版本统一在 `src/AppVersion.cs` 中维护，同时写入 EXE 文件版本和界面。

“检查更新”窗口提供 **自动更新** 开关，默认开启；旧配置没有该字段时也默认开启。关闭后取消在途自动检查／下载，停止负载检测，也跳过下次启动的自动安装，已下载文件保留。开关会保存并随配置导入导出，手动“检查更新”仍可使用。游戏模式只临时暂停自动更新，不改变这个开关；只有自动更新开启且游戏模式关闭时才恢复自动任务，退出游戏模式不会覆盖你明确关闭的设置。

自动更新允许运行时，托盘每次真正启动在后台检查一次 GitHub 正式 Release。发现新版只在打开的主面板里显示提示，不弹右下角浮窗、不发送托盘气泡，也不主动打开面板。自动检查失败也只在面板里说明，不影响音频管理；重复启动已有后台、打开／关闭面板不会重复检查。

连续 2 分钟没有键鼠操作，且没有待处理设备选择、正在应用的 Dolby 任务或最近 15 秒的音频设备事件时，再判断是否适合后台下载。全屏游戏、无边框全屏、全屏视频／演示（含副屏）会暂缓下载；CPU 总占用达到 50%、任一逻辑核达到 85%、同一 GPU 引擎合计达到 60%、任一磁盘繁忙达到 80% 或物理内存使用达到 80% 时也暂缓。连续两次负载采样较低才开始；计数器不可读时保守等待，可手动“检查更新”。

只在已有新版待下载时检测，每 30 秒最多采样一次，使用 Windows 自带性能计数器，不逐个扫描进程、不引入服务，也不轮询音频设备。正在操作键鼠、处理音频任务或已有全屏窗口时，跳过性能计数器；下载期间继续低频检查，检测到全屏／高负载／音频任务就取消本次传输，至少等 30 秒且恢复空闲后重试（并非瞬间检测）。没有新版或下载结束后停止检测并释放计数器。退出托盘取消尚未完成的下载。真正的下载失败至少间隔 5 分钟，每次启动最多尝试 3 次；主动避让不消耗失败次数，不触发重启。

同一次运行的自动重试复用同一个临时目录，已完整且摘要一致的 ZIP 直接复用；未完成的 ZIP 在该文件中重新下载，不不断新建目录，也不声称支持网络断点续传。整个更新缓存上限为 **256 MiB**，每个程序目录的 `update-backups` 上限为 **128 MiB**；下载、解压、生成助手和备份前预留空间，磁盘还需保留至少 64 MiB 余量。达到预留上限后停止新增更新文件，显示需要手动整理的目录。保留已有文件，不自动批量删除；用户音频配置备份不纳入这些限额。

下载校验通过后显示“下次启动时自动安装”。**关闭主面板不算退出：需从托盘退出，再启动程序，或下次登录 Windows 自启。** 下次启动先重新核验缓存，再备份、安装；自启方式继续只启动托盘，手动双击则打开面板。缓存绑定原 EXE 路径，移动目录后重新检查下载。自动安装失败不反复重试同一版本；原文件未修改或已完整恢复时尝试继续运行旧版，原因在下次打开面板时显示。不能确认文件完整时保留备份和结果记录，等待手动处理。

也可点击 **检查更新** 查看版本说明，主动选择 **下载并更新** 立即安装并重启。这个手动操作仍可在下载期间关闭窗口取消。所有更新工作复用现有托盘和短时更新助手，不新增常驻服务。

- 更新来源固定为 [EthenGod/AudioSwitch Releases](https://github.com/EthenGod/AudioSwitch/releases)，不安装草稿、预发布或较旧版本。先通过 GitHub 官方 `/releases/latest` 发布页判断版本，没有新版时不调用 REST API，避免共用出口 IP 的匿名 API 限额影响普通检查。本地版本更高时会明确显示本地版与最新正式版，而不是把本地构建称为已发布版本。
- 有新版时优先使用 [GitHub 最新正式版本接口](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) 获取附件信息；API 限流或暂时不可达时，读取相同版本官方附件页中与程序包对应的 SHA-256。网页仅显示取整后的文件大小，此时使用 32 MiB 下载上限和完整摘要校验，不把取整大小当作准确字节数。附件页结构变化、摘要缺失或不唯一时停止安装。不会要求登录、保存访问令牌或使用第三方镜像。
- 下载要求 GitHub 提供的 SHA-256 摘要匹配；校验包大小、固定文件清单、EXE 版本／x64 平台及原有 SVCL 校验值。拒绝路径穿越、重复文件、额外 DLL 或用户配置。该校验依赖 GitHub 发布账号和 HTTPS，不等同于独立的代码签名。
- 等待本目录的面板、后台、提示和音效辅助进程退出后再替换，不强制杀掉使用中的程序；其他文件夹的后台正在运行时停止更新。更新助手仅在本次安装期间运行。
- 替换前在程序目录 `update-backups\日期-唯一编号\` 保存并校验完整旧版；写入失败会恢复已经尝试修改的文件并逐项核验。恢复失败会明确说明，避免误报成功。若已退出后台而更新失败，请处理错误后重新打开声间。新文件装好但启动未确认时，保留备份并提示手动检查，不覆盖仍在运行的程序。
- `%LOCALAPPDATA%\AudioSwitch\settings.json`、配置备份、设备预设和 Dolby 参数不作为更新文件；重启后仍按已有的启动优先级和 Dolby 方案规则运行。下载缓存／结果记录保存在 `%LOCALAPPDATA%\AudioSwitch\updates\`，缓存和旧版备份不自动删除。

**v0.10.1 本身没有更新入口，需要先手动安装一次带此功能的版本；以后可以直接在软件内更新。** 发布时应先提交并推送全部对应源码，再创建匹配标签和正式 Release，不要仅推送源码或标签而遗漏程序附件。

维护者打包：修改 `src/AppVersion.cs` 中的版本号，然后运行：

```powershell
.\release.ps1
```

脚本会在独立 staging 目录构建、运行普通测试，并在项目的 `releases/v版本号/` 中生成两个待上传附件：

- `AudioSwitch-v版本号-win-x64.zip`：完整程序包，继续用于软件内更新和主程序修复。
- `AudioSwitch.exe`：可直接下载的单 EXE，与 ZIP 中的主程序完全相同。

以后每次发布只上传该版本子目录中的 ZIP 和 EXE。ZIP 内的 EXE 与单独的 EXE 均内嵌工具 Logo 图标，使用同一份程序；构建资源 `assets/AudioSwitch.ico` 包含 16–256 像素图标，无需另行上传。源码通过 GitHub 按该版本标签自动生成的 [Source code 下载入口](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases) 提供，无需再上传第三个附件；发布前必须提交并推送与构建对应的全部源码和构建必需文件，再创建匹配标签，并在说明中注明源码入口。

单 EXE 首次运行会离线释放运行配置和 `vendor/svcl/svcl.exe`，因此须下载到可写文件夹，保留 `AudioSwitch.exe` 文件名。不会要求补齐不影响运行的说明文件；原始第三方文件及许可已内嵌，可运行 `AudioSwitch.exe --licenses` 查看和复制许可文字。用户设置仍保存到原来的 LocalAppData 目录。待上传目录只保存原件，试运行请复制到其他目录。

完整程序包内直接放置原有 8 个发布文件，不增加外层目录；应用内更新仍使用该 ZIP。脚本核对 ZIP 内每个文件及独立 EXE 的哈希，不提交、不推送、不发布；版本目录已存在时停止，不覆盖、不清理旧目录。`-OutputDirectory` 指定其他输出根目录时，其下同样按 `v版本号/` 整理。历史 `artifacts/` 旧包保持原样。GitHub 上传完成后必须有 `sha256:` 附件摘要，否则软件拒绝安装。

`--update-process` 是独立更新助手的跨进程验证：需要先退出已有声间，测试只运行临时假面板、假后台及假新版程序，验证退出、中文／空格路径、替换、备份、启动确认和锁释放，不调用音频服务或用户配置。它不能代替真实 GitHub 下载和实际版本升级验收。

`--automatic-process` 同样需先退出声间，使用隔离假程序验证下次启动安装、只重启托盘的参数及损坏自动任务静默退出；普通测试另含空闲门槛、取消、重试上限、缓存篡改及失败不重复安装的测试。

`--update-online` 只读访问真实 GitHub 正式发布页及其附件页，验证版本与摘要解析，不下载或安装程序、不启动音频后台；需要网络连接，不包含在默认测试中。

### 新版声音工作台

主面板改为浅色背景、白色分组和蓝色操作按钮。当前默认设备以淡蓝色整行标记；设备名称、通话默认状态、优先级和预设集中展示，切换与设备设置并排，减少上下寻找。

- 顶部“全部设备 / 声音输出 / 麦克风输入”只筛选显示内容，不切换设备、不改配置。筛选在本次窗口内保留，后台刷新不会重置；待处理的接入或断开提示始终显示。
- 左侧集中放置三个自动切换开关和配置备份，开关旁直接解释其用途。

## 直接运行

下载 Release 的 `win-x64.zip` 程序包，完整解压后双击 `AudioSwitch.exe`；从源码按默认选项构建时，程序位于 `bin/AudioSwitch.exe`。请一起保留 `AudioSwitch.exe`、`AudioSwitch.exe.config`、`vendor` 文件夹以及 `LICENSE`、`NOTICE.txt`、`THIRD_PARTY.md`。依赖系统的 .NET Framework 4.8，不需要 Node、浏览器运行时或管理员权限。空间音效写入使用附带的 163 KiB 命令行组件，完整说明及许可见 `THIRD_PARTY.md`。

- **切换设备**：在“声音输出”或“麦克风输入”中点击“切换至此”。也可以右键托盘图标直接选设备。
- **设备优先级**：在“声音输出”和“麦克风输入”标题右侧点击“调整优先级”，选中设备后上移／下移，越靠上越优先。离线设备保留位置，列表会标注“离线”；重新连接后沿用原排序。主面板和托盘菜单也按这个顺序显示。
- **自动选择开关**：左侧“按设备优先级选择”默认开启，托盘菜单也可切换。开启时，设备接入／断开后自动选择同类在线设备中优先级最高的一个，并应用其音量和空间音效预设。保存排序或重新开启开关时立即应用；关闭后恢复原先的系统默认选择逻辑，仍可手动切换。
- **每设备预设**：每张卡片的“设备设置”可保存该设备的 0–100 音量及空间音效。可选择“仅保存”或“保存并应用”；当前默认设备已有预设时，也可点击卡片上的“应用预设”重新应用。
- **白名单**：每个设备的“设备设置 → 白名单 · 免打扰规则”提供“不加入白名单”“接受系统选择，不弹窗”“接入时自动切换，不弹窗”。输出和麦克风分别设置，默认均不加入白名单。选择“仅保存”后从下次设备变化生效；“保存并应用”还会立即切到此设备。
- **空间音效**：仅输出设备适用，按 Windows 返回的支持格式提供关闭、Windows Sonic、Dolby Atmos、DTS 等选项。第三方格式仍须安装并激活；无法应用时会明确报错。麦克风只提供输入音量设置。
- **新设备接入**：显示新旧设备选择。USB 耳机的输出和麦克风分别询问；同一轮重复通知不会反复创建提示。
- **右下角直接操作**：设备接入或当前设备断开时，弹出声间的小浮窗，直接提供设备下拉框、“使用新设备／切换到所选设备”、“继续使用旧设备”和“保持系统当前选择”等操作。不再自动打开完整管理面板；如需完整面板，可点击浮窗内的“打开面板”。
- **当前设备断开**：正在使用的默认输出或输入设备断开时，显示断开的设备和当前选择。可从下拉框选择同类在线设备，再点击“使用所选设备”；拔掉未使用的设备不会弹出提示。
- **选择其他设备**：接入新设备的提示里也可以直接选择其他在线设备。设备列表跟随连接状态更新，点击时还会再次检查，避免切换到已经断开的设备。
- **继续用旧设备**：恢复接入前记录的默认设备。即使 Windows 已经自行切换，也会尝试切回；旧设备已断开时会显示不可用。
- **保持系统当前选择**：仅关闭本次提示，不改变系统设置。没有可用设备时显示等待连接的说明和“知道了”。直接关闭窗口则保留待处理提示，可再次从托盘打开。
- **同时切换通话设备**：开启时同时改变系统普通、媒体、通话默认设备；关闭时只改变普通和媒体默认设备。
- **收回托盘**：关闭、最小化窗口或点击“收回托盘”都会退出界面进程。双击托盘图标重新打开。
- **彻底退出**：右键托盘图标，选择“退出”。
- **导出备份**：左侧点击“导出备份”，选择 JSON 文件位置。包含全部偏好、设备优先级、音量／空间音效预设及白名单，含离线设备记录。
- **导入设置**：左侧点击“导入设置”，选择配置文件，检查摘要后确认。完整替换配置，原配置先自动备份到设置目录的 `backups` 文件夹；备份失败或文件校验失败则不替换。规则立即更新，但不会立即切换设备或写入音量／音效。

`AudioSwitch.exe --background` 可以仅启动托盘。没有默认添加开机启动。

断开提示独立于“新设备接入时询问”开关。自动选择与是否询问也相互独立：关闭询问后，优先级仍会生效。关闭优先级后，声间不再自动干预 Windows 的设备选择，但保留接入／断开提示以及手动操作。如果关闭“同时切换通话设备”，自动和手动切换均保留通话默认值，仅通话默认设备的断开不触发提示。

v0.6 默认开启优先级，旧版设置升级后也默认开启。第一次建立顺序时把当前默认设备放在前面，其余按名称排列；后续新发现的设备追加到末尾。重启会按已保存的优先级检查当前选择，离线设备自动跳过。排序按设备 ID 保存，输出和输入互不影响。手动选择其他设备或在弹窗中恢复旧设备不会立即被改回；只有同类设备再次接入／断开、保存该类排序、重新开启优先级或重启时才会重新选择。关闭优先级不会恢复更早的设备，只停止自动干预，排序仍保留。

v0.7 增加两种设备白名单规则，按设备 ID 保存，重新接入或重启不会丢失：

- **接受系统选择，不弹窗**：检测到 Windows 将此设备选为同类日常默认设备时，接受系统结果，不再按普通优先级改回，不应用音量／音效预设，也不显示该类设备的接入或断开询问。默认设备变化较晚才到达时，会撤销该类已有提示。仅接入但没有被系统选中时，不触发此规则；系统一直使用此设备时，也不会屏蔽其他普通设备的接入提示。重启时保留已被系统选中的此类设备。
- **接入时自动切换，不弹窗**：检测到设备从离线变为在线后，主动切换并应用它的音量／空间音效预设。关闭全局优先级或接入询问后，此规则仍然生效。它优先于普通优先级及被动接受系统选择；同批接入多个同类自动切换白名单设备时，按已保存排序选一个。程序启动时已在线的设备不算新接入。

免打扰只处理相应的输出或输入提示，不隐藏另一类设备的变化。主动切换失败仍会显示错误并保留可用的手动提示；成功后不启动提示界面。白名单设备断开后，按剩余设备的规则和全局优先级处理。显式点击设备、保存排序或重新开启优先级仍按用户操作执行。将白名单改为“不加入白名单”即可恢复原有逻辑，不影响已保存的音量、音效和排序。

v0.7.1 修复白名单仍弹窗的两条路径：普通优先级回退到已在线的白名单设备时，也会免去该类询问；自动选择白名单设备时，如果保存的空间音效已不在设备支持列表中，则保留当前音效、继续应用音量并切换设备，成功后只在管理面板显示说明，不弹窗、不修改保存的预设。已处于目标音效时无需重复设置，不会仅因支持列表缺项而失败。手动应用预设、真实的默认设备切换失败及其他写入失败仍按原有错误处理，不会伪报成功。

v0.7.2 面板底部提示条增加“×”关闭按钮。关闭音效说明后会同步清除后台这条说明，定时刷新和重新打开面板不会重复显示；后续新发生的问题仍会提示。关闭错误提示仅收起当前提示，不更改设备或预设；同一条错误不会因刷新立即重现，新的操作失败仍会显示。

v0.8 统一日常配置与备份格式。唯一的活动用户配置仍为 `%LOCALAPPDATA%\AudioSwitch\settings.json`，使用 `Format: AudioSwitch.Settings`、`Version: 1` 和 `Settings` 字段；导出的文件与活动配置格式相同，可直接导入。旧版无版本号设置在首次启动时自动备份并迁移，也可直接导入。损坏文件不会被静默重置；不支持的版本、无效字段或超过 1 MiB 的文件会明确报错。详细结构见 [CONFIGURATION.md](CONFIGURATION.md)。

右下角提示是应用自己的可操作浮窗，位置避开主屏幕任务栏，不抢当前窗口焦点，也不进入 Windows 通知中心。处理完成后自动关闭；同时有输出和输入变化时，处理完一项后继续显示下一项。点击右上角 × 只收起浮窗，待处理选择仍可从托盘“有设备变化待处理…”重新打开。设备在选择期间断开时会更新选项，操作失败则保留浮窗并显示原因。

v0.4 将普通提示缩至约 360 × 211（100% 缩放），无可用设备时进一步收缩；错误信息出现时自动增高。设备下拉框与切换按钮同排，长名称可通过悬停说明或展开列表查看，旧设备信息可悬停“继续用旧设备”查看。保留全部选择操作。

v0.5 按 Windows 设备 ID 保存独立预设，重启或重新插入同一端点后继续使用。从主面板、托盘菜单、右下角提示选择设备，以及恢复旧设备时，都会应用各目标设备的已保存预设。先应用目标空间音效、音量，再切换默认设备；如果失败会尝试回退。未设置预设的设备保持原设置。音量和空间音效也都可分别选择保持当前值。音量操作不会主动解除静音。

“保持当前选择”仍仅关闭提示，不再次写入预设。单独修改默认设备、音量或空间音效不会触发优先级重新选择；设备接入／断开引起的系统选择则会按优先级检查，并应用目标预设。自动应用失败时显示原因，保留手动选择，不反复重试。“仅保存”不会改变声音；“保存并应用”会将该设备设为默认设备并应用预设。应用失败时保存的预设仍保留，可以修改后重试。

### v0.9：每个设备独立的 Dolby 方案

打开输出设备的“设备设置 → Dolby 方案”，勾选自动应用。可选择电影、自定义 1、自定义 2，设置 Dolby 总开关、环绕、人声增强、音量平衡、三项强度、电影智能均衡器，以及自定义 20 段均衡器。也可先在 Dolby Access 调好声音，回到这里点击“读取当前 Dolby 并填入”，再保存。读取时该设备必须是当前输出；读取本身不改声音。

v0.10.0 增加 **10 点 · dB（Dolby Access 方式）**。选自定义预设并勾选“应用均衡器”，就能按 32、64、125、250、500 Hz 和 1、2、4、8、16 kHz 填入 −12 到 +12 dB。修改后自动换算为后台 20 段；下拉框可切回“20 段 · 原始值（高级）”。“仅保存”留待下次使用该设备时应用，“保存并应用”立即使用。

20 段转为 10 点是近似读取，不能保留所有中间细节。只查看或切换视图不会改动原值，实际编辑 10 点才重新生成曲线。dB 显示两位小数，驱动最终以 1/16 dB 的整数步长保存；转换依据及本机核对结果见 [DOLBY-EQ.md](DOLBY-EQ.md)。没有新增后台进程或轮询。

“仅保存”留到下次应用；“保存并应用”选择设备后在后台应用 Dolby。跟随系统默认输出、优先级、白名单、设备断开后的回退和程序启动都能自动应用。主面板显示已开启 Dolby 自动方案及正在应用状态。每个项目都可保持不变，关闭该设备的勾选即可停止自动应用。旧配置默认不开启，不会自动更改原来的调音。

Dolby 调用使用短暂的独立辅助进程，串行处理且只保留最后的待应用设备。每次写入前核对当前输出，失败尝试恢复；不支持的设备或版本保留原设置并在面板给出可关闭说明，不弹出免打扰设备提示。辅助进程操作后退出，托盘空闲时不轮询 Dolby，不启动 Dolby Access 界面。所有方案包含在原有导入／导出备份内。

当前适配本机 Dolby Access **3.27.12250.0** 的 DAX 组件，按文件校验值锁定协议版本；升级后组件变化会停止 Dolby 操作而保留方案。这里只控制驱动识别的 DAX 设备，并不代表所有支持 Dolby Atmos 的 USB／蓝牙耳机都能用。尚未开放游戏、音乐、语音、动态、自定义 3 及低音增强；不修改激活／授权。Dolby 内容自动切换开启后可能覆盖手动预设。此功能与 Windows 空间音效选择分别设置，不会自动开启 Atmos。

2026-09-23 已通过新版辅助进程实测电影 ↔ 原自定义预设，独立进程读回确认，并恢复全部原音效、强度、均衡器及 Runtime 的 ProfileList。快速切换、失败恢复、配置校验、UI 保存有自动测试；真实硬件插拔仍需按手动测试清单验证。

`--dolby-smoke` 是可选的本机联调测试：要求没有已运行的声间实例、当前 DAX 输出处于已支持的预设且三个输出角色一致。它临时保存电影方案，经真实后台应用后恢复原配置与 Dolby 参数；会短暂改变声音，普通测试不会执行。2026-09-23 最终合并运行 `--render --lifecycle --dolby-smoke` 通过 256 项检查；关闭面板后后台实测工作集约 47 MiB、私有内存约 32 MiB。

## 实现与占用

- **后台进程**：原生托盘、Windows Core Audio 事件订阅、设备快照、本地命名管道。空闲时不轮询设备；首条设备事件到来后合并约 150 毫秒再刷新，后续连续事件不重置等待。替代了旧版不断重置的 900 毫秒等待。
- **界面进程**：原生 WinForms 自绘浅色界面。仅在窗口打开期间每 1.5 秒从后台读取状态。窗口关闭后释放整个进程及其 UI 资源。
- **提示进程**：右下角可操作浮窗由单独的 `--prompt` 进程托管，显示前加载首份快照，第一帧即有设备和按钮；只在显示期间每 0.3 秒刷新。处理完所有选择、手动关闭或后台退出后，提示进程退出。不预留常驻的界面进程。提示可以与管理面板共存，但不会为了显示通知而启动管理面板。
- **速度说明**：150 毫秒是程序内部的事件合并时间，不是实际插拔到弹窗的总耗时；驱动上报、设备枚举、进程启动及系统负载仍会影响速度。测试会模拟连续事件并测量首次刷新，以及独立提示进程启动到 UI 空闲的时间。
- **通信**：命名管道仅允许当前 Windows 用户访问，并按登录会话隔离；请求与响应有超时限制。
- **资源**：无 Electron / WebView。2026-09-20 本机首次生命周期测试中，后台工作集约 40 MiB，私有内存约 28 MiB。实际占用因系统和设备数量而异；不是固定上限。
- **设置**：存放于 `%LOCALAPPDATA%\AudioSwitch\settings.json`；错误日志为同目录的 `error.log`。不联网，不读取麦克风音频，不收集遥测。
- **预设实现**：音量用 Core Audio；空间音效状态用 WinRT `SpatialAudioDeviceConfiguration`，需要 Windows 10 1809 或以上；音效写入调用固定校验值的本地 `svcl.exe` 后退出，并通过 Windows API 读回确认。没有启用音效预设或目标音效已经一致时不会启动该组件。

## 已知边界

- 默认设备切换使用 Windows 未公开的 `IPolicyConfig` 接口，已隔离在 `AudioInterop.cs` 中；将来的系统版本可能需要调整。切换会检查结果，并在部分失败时尝试恢复。
- 本轮自动验证没有实际插拔硬件，也没有更改电脑上的默认设备。发布前需在实际 USB / 蓝牙设备上按 `MANUAL-TESTS.md` 验证。
- 接入判断以“音频端点从不可用变为可用”为准。启用设备、蓝牙重新连接也可能提示；部分模拟耳机插孔若没有向 Windows 报告独立端点变化，无法区分插拔。
- 接入或断开前默认设备取自上一轮稳定快照；将同轮系统通知合并后再判断。极少数驱动若先更改默认设备、很久后才报告端点上线或离线，旧设备记录或断开检测可能不准确。
- 已在应用内单独指定输出设备的软件，可能不跟随 Windows 默认值。播放中的程序也可能需要重新开始播放。
- 目前按系统 DPI 缩放，跨不同缩放比例的显示器移动后，可能需要关闭并重新打开窗口。

## v0.10.1 Dolby 稳定性修复

读取旧参数后、写入之前再次检查取消及当前输出，减少切换过程中旧任务继续写入的机会。读取当前方案时校验预设与自定义槽位是否变化，发生变化时要求重新读取。读取期间暂时锁定 Dolby 编辑区，失败后保留原方案。驱动返回无效原值时停止写入，恢复读回异常时明确报告未能恢复。均衡器格式和换算方法保持不变。
